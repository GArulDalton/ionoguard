# IONOGUARD

**Scintillation Aware LEO Satellite Selection for Direct to Cell Links with Conformal Risk Control**

Code and results for the manuscript by Arul Dalton. G (Department of Computer Science and Engineering, Saveetha Engineering College, Chennai, India).

IONOGUARD is a learning-based controller for direct-to-cell (D2C) low Earth orbit (LEO) satellite links under equatorial plasma-bubble scintillation. It

1. rebuilds a drift-compensated S4 scintillation map from delayed GNSS monitor reports, with self-supervised estimation of the zonal drift;
2. refines the map with a gradient-boosted correction model;
3. projects every candidate link's ionospheric pierce point along its ephemeris over a 15 s horizon;
4. calibrates the forecast with **regime-conditional conformal risk control** (Algorithm 2), so that the expected block failure probability stays below a target ε in quiet, moderate and disturbed conditions;
5. selects the serving satellite and the MCS in a receding-horizon manner, or defers transmission (Algorithm 1).

## Repository layout

```
src/
  sim.py      constellation, link geometry, plasma-bubble field, fading tables,
              GNSS monitor network, drift-compensated kernel map
  train.py    correction-model training and regime-conditional conformal risk calibration (Algorithm 2)
  run.py      test-night simulator, IONOGUARD (Algorithm 1), baselines and ablations, metrics
scripts/
  train_models.py      train + calibrate models for scenarios S1-S3
  run_main.py          10 schemes x 3 scenarios x 3 held-out nights
  run_sweeps.py        sensitivity to target eps, monitor density M, latency L
  run_trace.py         one traced night (field snapshot and time series)
  timing.py            per-epoch runtime
  summarize.py         aggregate per-night outputs into results/*.json
  make_figures.py      result figures
  make_block_diagrams.py   scenario and pipeline block diagrams
results/   aggregated results used in the paper
figures/   figures used in the paper
```

## Installation

```bash
git clone https://github.com/GArulDalton/ionoguard.git
cd ionoguard
pip install -r requirements.txt
```

Python 3.10 or later. Everything runs on a single CPU core; no GPU is needed.

## Reproducing the paper

```bash
cd scripts
python train_models.py      # about 5 min per scenario
python run_main.py          # about 6-7 min per test night (9 nights)
python run_sweeps.py        # about 2-4 min per run (6 runs)
python run_trace.py
python timing.py
python summarize.py
python make_figures.py
python make_block_diagrams.py
```

`bash run_all.sh` runs the whole pipeline (roughly 2-3 hours on one core). Add `--quick` to `train_models.py` and `run_main.py` for a 30-minute-night smoke test; quick results are not comparable with the paper.

All random seeds are fixed (training nights 1001-1003, calibration nights 1011-1013, test nights 1101-1103 for S1; +1000 and +2000 for S2 and S3).

## Notes on the results files

`results/summary.json` holds mean ± standard deviation over the three test nights per scenario, `results/extra_sweeps.json` the sensitivity studies, `results/trace_stats.json` the traced-night statistics and `results/timing.json` the runtime. The per-night raw outputs are regenerated by the scripts into `results/nights/`. Re-training uses a fixed `random_state`, so re-runs reproduce the reported numbers up to small differences in the boosted-tree fit.
